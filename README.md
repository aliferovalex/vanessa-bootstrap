# vanessa-bootstrap: проекты 1С в EDT

Форк [vanessa-opensource/vanessa-bootstrap](https://github.com/vanessa-opensource/vanessa-bootstrap)
с инициализацией из базы или хранилищ 1С, Git LFS и сборкой CF/CFE из EDT.

Основной сценарий: клонируйте форк в каталог своего проекта и запустите
инициализатор **в этом же каталоге**. Существующие `.git`, ветка и история
сохраняются; исходники добавляются отдельным коммитом инициализации.

## Требования

- Windows PowerShell 5.1 или PowerShell 7.
- Git и Git LFS: `git --version`, `git lfs version`.
- Толстый клиент 1С нужной полной версии, с доступом к лицензии при её запросе.
- Современный EDT CLI `1cedtcli.exe` и подходящая Java.

Инициализатор не устанавливает эти программы. EDT Start нужен только для
регистрации рабочей области. OneScript и **vanessa-runner 2.6.x** нужны для
`prepare.cmd`, `update.cmd` и `test.cmd`; для импорта и `build.cmd` они не нужны.
vanessa-runner 3.x пока не поддерживается: его команды и настройки отличаются.
Заранее настройте имя/email Git либо передайте `-GitUserName` и `-GitUserEmail`.

## Установка и быстрый запуск

```powershell
git clone https://github.com/aliferovalex/vanessa-bootstrap.git Demo
cd Demo
.\initialize.cmd -AskCredential
```

Скрипт предложит выбрать тип источника по номеру: `1` — файловая база,
`2` — серверная база, `3` — хранилище. Затем запросит его адрес,
пути к Конфигуратору и EDT CLI. Каталог проекта — корень клонированного репозитория. Учётные данные
запрашиваются для базы или хранилища в зависимости от выбранного источника.
`-AskCredential` запрашивает имя пользователя 1С в консоли и пароль скрытым
вводом. Для `Server` и `File` укажите пользователя информационной базы, а не
Git, хранилища или Windows; префикс домена добавлять автоматически не нужно.
Параметр `-UserName` задаёт предлагаемое имя. Пустой пароль допустим.
Если Конфигуратор сообщает «Пользователь ИБ не идентифицирован», проверьте
вход под тем же пользователем через обычный Конфигуратор в ту же базу.
Инициализатор передаёт имя и пароль через `/N` и `/P`, отключая вход ОС
параметром `/WA-`, чтобы использовать именно выбранного пользователя 1С.
Для Java можно указать отдельный ini-файл через `-EdtIniFile`.

Для входа в базу от текущего пользователя Windows используйте вместо
`-AskCredential` параметр `-UseOSAuthentication`:

```powershell
.\initialize.cmd -FreshHistory -GitBranch main -UseOSAuthentication
```

Конфигуратор получает `/WA+` без `/N` и `/P`; имя и пароль не запрашиваются.
В информационной базе у соответствующего пользователя должна быть настроена
аутентификация ОС и право запуска Конфигуратора. Используется учётная запись,
от которой запущена консоль, без переключения пользователя Windows.
Режим доступен для `File` и `Server`, несовместим с `-AskCredential`,
`-UserName` и `-Password`. Для источника `Repository` нужны отдельные
учётные данные хранилища.

При источнике `File` или `Server` выгружается текущая конфигурация базы,
включая непомещённые изменения. Реквизиты хранилища не запрашиваются и не
передаются Конфигуратору. Старые `-AskRepositoryCredential`, `-RepositoryUserName`,
`-RepositoryPassword` и `-RepositoryAddress` принимаются с предупреждением
и игнорируются для этих источников. Привязка базы сохраняется.

Платформа может попытаться подключиться к сохранённому хранилищу и записать
«Соединение с хранилищем конфигурации не установлено». Само предупреждение
не считается ошибкой: учитываются код завершения и результат XML-выгрузки.
При тайм-ауте импорт не продолжается: частичная выгрузка не публикуется.
В каталоге диагностики `dump-main.launch.json` содержит аргументы без паролей,
`dump-main.result.json` — код завершения и признак тайм-аута,
`dump-main.export.json` — количество и общий размер выгруженных файлов.
Для большой конфигурации можно задать `-TimeoutSeconds 7200` вместо 1800.
Это увеличивает время ожидания, но не устраняет другие ошибки запуска.
`stdout`, `stderr` и журнал Конфигуратора сохраняются также после тайм-аута.
Выгрузка без установленного соединения с хранилищем проверена на файловой базе
8.3.27.2342; серверная база 8.3.27.1936 отдельно не проверена.
Для запуска без меню по-прежнему доступен `-InfobaseType File/Server/Repository`
(укажите одно значение).

При интерактивной инициализации базы появится список её расширений.
Введите `1,3` для выбора по номерам, `*` или Enter для всех, `0` для проекта без
расширений. При запуске с явно заданным типом источника включите список через
`-SelectExtensions`. Для автоматизации есть `-Extensions` и `-NoExtensions`.
Без выбора по умолчанию берутся все расширения. Список обнаруживается после
выгрузки XML; в EDT преобразуются только выбранные расширения.

## Инициализация из базы с параметрами

Запускать из каталога клонированного шаблона, заменив пути на свои:

```powershell
$options = @{
    TemplateDirectory = (Get-Location).Path
    InfobaseType = 'File'
    Infobase = 'D:\Bases\Demo'
    ProjectName = 'Demo'
    DesignerPath = 'C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe'
    EdtCliPath = 'D:\EDT\1cedtcli.exe'
}
.\project-init\Initialize-Project.ps1 @options -Preview
.\project-init\Initialize-Project.ps1 @options -AskCredential -SelectExtensions
```

Для серверной базы: `InfobaseType = 'Server'`, `Infobase = 'server\base'`.
Исходная база не обновляется, захват и помещение не выполняются. Во время
выгрузки конфигурация и расширения не должны меняться.

Используйте корневой `initialize.cmd`: он включает файлы шаблона в результат.
При прямом вызове PS1 для этого нужен `-TemplateDirectory`, как выше.

## Инициализация непосредственно из хранилищ

```powershell
.\initialize.cmd -InfobaseType Repository `
    -Infobase 'https://server/repo/repo.1ccr/Main' `
    -RepositoryVersion 12 `
    -ProjectName Demo `
    -DesignerPath 'C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe' `
    -EdtCliPath 'D:\EDT\1cedtcli.exe' `
    -AskCredential
```

`-RepositoryVersion -1` получает актуальное состояние; положительный номер
фиксирует запрошенную версию. Для расширений добавьте
`-ExtensionRepositoryFile 'D:\Settings\repositories.json'` с массивом:

```json
[{"name":"ExtensionA","url":"https://server/repo/repo.1ccr/ExtensionA","version":4}]
```

Основное хранилище не предоставляет список независимых хранилищ расширений:
здесь они задаются явно. Все хранилища читаются одной учётной записью и одной
версией платформы. Для общего прокси заранее настройте привязки хранилищ проекта.

CF/CFE читаются в отдельную временную базу. Привязка, захват и помещение не
выполняются. Адреса и запрошенные версии сохраняются без паролей; основы
синхронизации автоматически подтверждёнными не считаются.

## Что создаётся

```text
Demo/
  .git/
  .gitattributes
  project-init.json
  env.json
  build.cmd, prepare.cmd, update.cmd
  project-init/, tools/, tests/, features/
  src/
    cf/                     # основной проект EDT
    cfe/ExtensionA/         # проект расширения
```

Манифест содержит полную версию платформы, пути компонентов и коммит шаблона.
Git LFS настраивается до первого добавления исходников; отключение: `-NoGitLfs`.
Правила окончаний строк сохраняются. Глобальные настройки Git не меняются.

При инициализации на месте сохраняются история, текущая ветка и remotes.
`-SkipInitialCommit` оставляет подготовленные изменения в индексе без нового
коммита. При интерактивном запуске скрипт предложит адрес Git проекта.
Для настройки адреса отдельно используйте команду ниже; прежний `origin`
сохраняется как `bootstrap`, затем `origin` указывает на ваш проект:

```powershell
cd D:\Projects\Demo
.\tools\git-project-init.cmd -ProjectRemoteUrl https://git.example.org/team/demo.git
git push -u origin HEAD
```

Перед началом рабочая копия должна быть чистой, `project-init.json` должен
отсутствовать, а `src/cf` и `src/cfe` могут содержать только заглушки шаблона.
Выгрузка и подготовка коммита выполняются вне проекта; перед применением повторно
проверяются ветка и HEAD. Готовый коммит применяется только fast-forward.

Для создания проекта отдельно передайте `-TargetDirectory D:\Projects\Other`.
Этот каталог должен отсутствовать; результат получит новую ветку `main`, новую
историю и не будет иметь remote. Исходный клон в этом режиме не меняется.

`tools/git-project-init.cmd` также настраивает Git только для проекта:
`quotepath=false`, `autocrlf=true`, `safecrlf=true`, `longpaths=true` и Git LFS.
Имя/email берутся из существующих настроек или параметров `-GitUserName` и
`-GitUserEmail`. Глобальные настройки, алиасы и `http.postBuffer` не меняются.
Старое имя `tools/git-global-init.cmd` теперь вызывает эту локальную настройку.

Для регистрации рабочей области добавьте `-RegisterEdtStart`; если лаунчер
запущен — закройте его или добавьте `-RestartEdtStart`. База отладки настраивается
отдельно. Обмен Git ↔ хранилища включается в сервисе после подтверждения основ.

## Сборка и работа с базой разработки

В созданном проекте задайте пути для текущего сеанса и запустите сборку:

```powershell
$env:ONEC_DESIGNER = 'C:\Program Files\1cv8\8.5.1.1529\bin\1cv8.exe'
$env:ONEC_EDT_CLI = 'D:\EDT\1cedtcli.exe'
# При необходимости: $env:ONEC_EDT_INI = 'D:\Settings\edt-cli.ini'
.\build.cmd
```

| Команда | Действие |
|---|---|
| `build.cmd` | EDT → XML, сборка CF/CFE в отдельной временной базе |
| `prepare.cmd` | Сборка, подготовка базы разработки, загрузка расширений и обновление в Предприятии |
| `update.cmd` | Сборка и обновление существующей базы разработки |
| `test.cmd` | Запуск сценариев через vanessa-runner 2.6.x |
| `open.cmd` / `designer.cmd` | Открытие настроенной базы разработки |

Для работы с базой сначала настройте `env.json`: по умолчанию используется
`build/ib`. Команды подготовки и обновления изменяют эту базу. Версия платформы
в новых проектах заполняется инициализатором и должна совпадать с Конфигуратором.

Артефакты и журналы сохраняются в `build/edt-<UUID>`, `result.json` появляется
после успеха. Исходники не перезаписываются. Экспорт без сборки:
`tools/Export-Edt.ps1 -EdtCliPath ...`. Новые EDT-команды рассчитаны на Windows;
shell-скрипты сохраняют прежний XML-сценарий upstream.

## Обновление и диагностика

До инициализации клон форка обновляется командой `git pull --ff-only origin master`.
После настройки Git проекта `origin` принадлежит проекту; обновления шаблона
получайте через `bootstrap` и проверяйте перед слиянием.
Для разработки форка можно добавить исходный репозиторий:

```powershell
git remote add upstream https://github.com/vanessa-opensource/vanessa-bootstrap.git
git fetch upstream
```

Слияние upstream выполняйте после проверки совместимости. Перед инициализацией
завершите локальные изменения шаблона коммитом. Созданные проекты автоматически
не обновляются и не перезаписываются.

Временные выгрузки и журналы остаются рядом с проектом в `.project-init-<UUID>`.
Они содержат исходники; после проверки их можно удалить. Пароли в манифест
не записываются, но при запуске 1С передаются процессу платформы и доступны
административным средствам ОС. Не добавляйте пароли в `env.json` и шаблон.

Подробности: [параметры и ограничения](doc/EDT-INITIALIZATION.md).

## Выбор ветки при инициализации

Передайте `-GitBranch`, например:

```powershell
.\initialize.cmd -GitBranch main -AskCredential
```

При интерактивном запуске имя ветки также запрашивается с текущим значением
по умолчанию. Без параметра в клоне сохраняется текущая ветка; для отдельного
нового каталога используется `main`. `-GitBranch develop` или `feature/start`
задаёт другое имя.

В клоне новая ветка создаётся из подготовленного коммита инициализации только
после успешной выгрузки и проверок. Исходная ветка остаётся на прежнем коммите.
Чтобы использовать уже существующую другую ветку, сначала переключитесь на неё
через `git switch`, затем запускайте инициализацию. Скрипт не перезаписывает
существующие ветки. С `-SkipInitialCommit` новая ветка остаётся на исходном
коммите, а подготовленные изменения находятся в индексе.

Отдельный репозиторий: `initialize.cmd -TargetDirectory D:\Projects\Other -GitBranch develop`.
Параметр не создаёт ветку на сервере Git и не выполняет push.

## Новый проект без истории шаблона

```powershell
.\initialize.cmd -FreshHistory -GitBranch main -AskCredential
```

`-FreshHistory` создаёт независимый Git в этом же каталоге: один начальный коммит
с готовым проектом, без старых коммитов, веток и remotes шаблона. Без флага
история сохраняется. По умолчанию новая ветка называется `main`; другое имя
задаётся через `-GitBranch`. `-SkipInitialCommit` оставляет новый Git без коммитов
с подготовленными файлами в индексе.

Сначала все исходники и Git готовятся во временном каталоге. Старый `.git`
сохраняется вне проекта в `.project-init-<UUID>/previous-project/.git`; путь
выводится после применения. Резервная копия содержит прежнюю историю и настройки,
не входит в новый репозиторий и не отправляется при push. После проверки её
можно удалить самостоятельно. Ошибка применения вызывает восстановление
прежних файлов и `.git`; сведения о публикации — в `fresh-history-publication.json`.

Режим доступен для самостоятельного клона без дополнительных Git worktrees.
Рабочая копия должна быть чистой, исходники и манифест должны отсутствовать.
Для подключения Git-сервера задайте `-ProjectRemoteUrl` либо выполните
`tools/git-project-init.cmd` после инициализации. При `-FreshHistory` старые
remotes остаются только в резервной копии. С явным другим `-TargetDirectory`
история и так создаётся заново, поэтому дополнительный флаг там не требуется.
