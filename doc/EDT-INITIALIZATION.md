# Инициализация проекта EDT

Этот форк добавляет импорт существующей базы в структуру vanessa-bootstrap.
По умолчанию проект инициализируется в клонированном каталоге шаблона с сохранением его истории Git. Требуются Windows PowerShell
5.1 или 7, Git, Git LFS, толстый клиент 1С и современный 1cedtcli.exe.

```powershell
git clone https://github.com/aliferovalex/vanessa-bootstrap.git
cd vanessa-bootstrap
.\initialize.cmd -InfobaseType File -Infobase D:\Bases\Demo -DesignerPath C:\Tools\1C\bin\1cv8.exe -EdtCliPath C:\Tools\EDT\1cedtcli.exe -ProjectName Demo -AskCredential
```

Сначала можно добавить `-Preview`. Для отдельного режима `-TargetDirectory` каталог назначения должен отсутствовать.
Пути программ в примере замените на свои. Для серверной базы используйте
`-InfobaseType Server -Infobase server\base`.
Без `-InfobaseType` появляется меню: `1` — File, `2` — Server,
`3` — Repository. Некорректный номер можно ввести повторно.

Недостающие параметры также запрашиваются внутри скрипта, даже если тип источника
передан явно. Для базы выбирается вход ОС (по умолчанию) или имя и пароль 1С.
При инициализации в каталоге шаблона выбирается сохранение истории Git
(по умолчанию) или новая история с резервной копией прежней. Затем вводится
ветка: Enter сохраняет текущую ветку либо выбирает `main` для новой истории.
Явно переданные параметры не запрашиваются повторно; это относится и к
переключателям со значением `$false` при вызове PS1. Для источника `Repository`
вход ОС не предлагается. В отдельном новом каталоге нет вопроса о замене истории.

`-NonInteractive` отключает автоматические вопросы: укажите `InfobaseType`,
`Infobase`, `DesignerPath`, `EdtCliPath`. Остальные отсутствующие настройки
используют прежние значения по умолчанию (сохранение истории, текущая ветка
или `main` для новой истории, стандартная аутентификация платформы).
Явные `-AskCredential`, `-SelectExtensions`
запрашивают ввод и в этом режиме; для полностью автоматического сценария
вместо них передайте значения, пароль — `SecureString`. `-Preview` не задаёт
новые вопросы и показывает уже переданные настройки и значения по умолчанию.

Для аутентификации ОС укажите `-UseOSAuthentication` вместо `-AskCredential`:

```powershell
.\initialize.cmd -FreshHistory -GitBranch main -UseOSAuthentication
```

При выгрузке основной конфигурации и расширений Конфигуратору передаётся
`/WA+`, без `/N` и `/P`. Используется текущая учётная запись Windows;
в базе у пользователя должны быть настроены аутентификация ОС и доступ
к Конфигуратору. Режим поддерживает `File`/`Server`. Нельзя совмещать с `-AskCredential`, `-UserName`,
`-Password`. В явном режиме имени/пароля 1С передаётся `/WA-`.
Для `File`/`Server` экспортируется текущая конфигурация базы.

При тайм-ауте частичная выгрузка не импортируется в EDT и не публикуется в Git.
Проверьте `dump-main.result.json` (код завершения, тайм-аут),
`dump-main.export.json` (число и размер файлов) и `dump-main.designer.log`
в каталоге диагностики. Для длительной выгрузки доступен `-TimeoutSeconds 7200`.

В основном режиме сохраняются `.git`, текущая ветка и remotes. Исходники
готовятся в отдельном временном клоне, затем коммит применяется fast-forward.
Рабочая копия должна быть чистой, манифест и исходники должны отсутствовать.
Заглушки README в `src/cf` и `src/cfe` заменяются EDT-проектами. Перед публикацией
повторно проверяются HEAD и ветка. `-SkipInitialCommit` оставляет изменения
в индексе. `-ProjectRemoteUrl` меняет `origin`, сохраняя прежний как `bootstrap`.
В интерактивном запуске адрес предлагается в конце; пустой ответ сохраняет origin.

Явный `-TargetDirectory` с новым адресом включает отдельный режим:
копируются отслеживаемые файлы шаблона, создаётся новая история в выбранной ветке
(по умолчанию `main`) без remote, если не задан `ProjectRemoteUrl`.
Перед инициализацией завершите локальные изменения шаблона коммитом.

Основная конфигурация находится в `src/cf`, расширения — в `src/cfe/<имя>`.
По умолчанию берутся все расширения. `-NoExtensions` исключает их,
`-Extensions` позволяет выбрать список при прямом запуске PowerShell-скрипта.
Для выбора из списка подключённых к базе расширений добавьте `-SelectExtensions`.
После выгрузки скрипт покажет имена с номерами: введите `1,3`, `*` для всех
или `0` для проекта без расширений. Некорректный ввод можно повторить.
При полностью интерактивном запуске `initialize.cmd` без параметров этот выбор
появляется автоматически. В автоматических сценариях без `-SelectExtensions`
поведение сохраняется: все расширения либо явно заданный `-Extensions`.
Выбор выполняется перед преобразованием в EDT; для обнаружения списка XML
всех расширений сначала выгружается во временный каталог.
`-NoGitLfs` отключает LFS. Существующие правила окончаний строк сохраняются.

Поддержан также прямой импорт из хранилищ:

```powershell
.\initialize.cmd -InfobaseType Repository -Infobase https://server/repo/repo.1ccr/Main -RepositoryVersion 12 -RepositoryUserName reader -TargetDirectory D:\Projects\Demo -DesignerPath C:\Tools\1C\bin\1cv8.exe -EdtCliPath C:\Tools\EDT\1cedtcli.exe
```

Для источника `Repository` пароль хранилища запрашивается скрыто. Можно использовать `-AskRepositoryCredential` или `-AskCredential`:
имя запрашивается в консоли, пароль вводится скрыто. Для источника `Repository`
это пользователь хранилища; для `File`/`Server` — пользователь информационной
базы 1С. При ошибке «Пользователь ИБ не идентифицирован» сначала проверьте
эти имя и пароль в обычном Конфигураторе той же базы. Для входа Windows
в базу используйте отдельный параметр `-UseOSAuthentication`.
При прямом вызове PS1 пароль можно передать как SecureString; в файлы проекта он
не записывается. Платформа получает пароль аргументом процесса, доступным
административным средствам ОС. URL со встроенными учётными данными запрещены.

`-RepositoryVersion -1` (по умолчанию) получает актуальное состояние. Для
воспроизводимости укажите положительный номер версии. Для расширений передайте
`-ExtensionRepositoryFile D:\Settings\repositories.json` с массивом:

```json
[{"name":"Extra","url":"https://server/repo/repo.1ccr/Extra","version":4}]
```

Все хранилища читаются одной учётной записью, одной версией платформы. Список
расширений задаётся явно: основное хранилище не предоставляет их перечень.
Создаётся отдельная временная база, сначала читается конфигурация, затем CFE
расширений в её контексте. Захват, привязка и помещение не выполняются.
Для обращения через общий прокси заранее настройте разрешённые привязки проекта;
неизвестный alias прокси отклоняет. Прямой адрес публикации 1С тоже поддерживается.

Манифест сохраняет адреса и запрошенные версии без паролей. Он не утверждает,
что версии разных хранилищ являются согласованным снимком. Основы синхронизации
по-прежнему подтверждаются отдельно в сервисе.

Для регистрации рабочей области добавьте `-RegisterEdtStart`.
Если EDT Start запущен, закройте его либо добавьте `-RestartEdtStart`.
Личную базу отладки настройте отдельно. Автоматический обмен с хранилищем
не включается: основы синхронизации подтверждаются в сервисе.

Для EDT-проектов Windows-команды `build.cmd`, `prepare.cmd`, `update.cmd`
вызывают `tools/Run-Project.ps1`. Задайте `ONEC_EDT_CLI`, `ONEC_DESIGNER` и при
необходимости `ONEC_EDT_INI` в окружении или передайте одноимённые параметры
`-EdtCliPath`, `-DesignerPath`, `-EdtIniFile`.

`build.cmd` копирует EDT-исходники в отдельный рабочий каталог, преобразует
конфигурацию и расширения в XML, собирает CF/CFE в новой файловой базе. Версия
Конфигуратора должна точно совпадать с `platformVersion`. OneScript для этой
сборки не требуется. Артефакты и журналы находятся в `build/edt-<UUID>`;
`result.json` появляется только после успешного выполнения. Исходники не
перезаписываются, предыдущие сборки не удаляются.

`prepare.cmd` и `update.cmd` после сборки передают XML в vanessa-runner,
загружают расширения и выполняют обновление в режиме Предприятия. Эти команды
изменяют базу из `env.json` (по умолчанию `build/ib`); настройте её перед запуском.
Они используют API **vanessa-runner 2.6.x**, например 2.6.1, и требуют OneScript.
vanessa-runner 3.x использует другие команды и здесь пока не поддерживается.
Для дополнительных параметров runner используйте PowerShell:
`tools/Run-Project.ps1 -Action Prepare -RunnerArguments @('--db-user','Developer')`.

Отдельный экспорт без сборки: `tools/Export-Edt.ps1 -EdtCliPath ...`.
Старые XML-проекты продолжают использовать прежние команды bootstrap.
Shell-скрипты пока сохраняют прежнее ограничение для EDT; новая сборка рассчитана
на Windows. Команда `test` также использует vanessa-runner 2.6.x.

Пароли и параметры личных баз в шаблон не добавляются. Промежуточные выгрузки
и журналы остаются рядом с новым проектом в `.project-init-<UUID>`;
после проверки их можно удалить. Они не входят в репозиторий проекта.

Обновления upstream получают в рабочую копию шаблона отдельно:
`git fetch upstream`, затем проверка и слияние выбранного коммита.
Существующие проекты автоматически не обновляются и не перезаписываются.

## Справочник параметров инициализатора

Ниже перечислены все 35 параметров `project-init/Initialize-Project.ps1`.
`initialize.cmd` передаёт ему аргументы и автоматически задаёт `TemplateDirectory`
как каталог клонированного шаблона. Для другого шаблона вызывайте PS1 напрямую.
Пути с пробелами заключайте в кавычки.

Параметры типа `switch` включаются одним флагом, например `-FreshHistory`.
При прямом вызове PS1 можно передать явное отключение: `-FreshHistory:$false`
или `-UseOSAuthentication:$false`. Такой ответ не запрашивается повторно.
Стандартные общие параметры PowerShell, например `-Verbose` и `-ErrorAction`,
не входят в эти 35 настроек проекта.

### Источник, каталоги и программы

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-InfobaseType <string>` | Источник: `File`, `Server` или `Repository`. Значения по умолчанию нет. | Да, если не передан: меню `1` / `2` / `3`. |
| `-Infobase <string>` | Для `File` — каталог с `1Cv8.1CD`; для `Server` — `сервер[:порт]\имя`; для `Repository` — URL `tcp://`, `http://` или `https://` без встроенных учётных данных. | Да, если не передан. |
| `-TargetDirectory <string>` | Каталог результата. Без параметра — каталог шаблона, инициализация в нём. Явный другой каталог должен отсутствовать, а его родитель — существовать. | Нет. |
| `-TemplateDirectory <string>` | Каталог чистой Git-копии шаблона. CMD задаёт его автоматически. При вызове PS1 без `TargetDirectory` используется корень форка; при отдельном `TargetDirectory` без шаблона создаются только EDT-исходники и настройки инициализатора. | Нет. |
| `-ProjectName <string>` | Имя EDT-проекта основной конфигурации. По умолчанию `Configuration`. Проекты расширений получают имена `<ProjectName>_<ИмяРасширения>`. | Нет. |
| `-DesignerPath <string>` | Путь к `1cv8.exe`. Версия платформы определяется по этому файлу. | Да, если не передан. |
| `-EdtCliPath <string>` | Путь к современному `1cedtcli.exe`; BAT/CMD-обёртки не поддерживаются. | Да, если не передан. |
| `-EdtIniFile <string>` | Существующий ini-файл EDT CLI, например с настройкой Java. По умолчанию не задан. | Нет. |
| `-GitPath <string>` | Путь или имя исполняемого файла Git. По умолчанию `git` из `PATH`. | Нет. |

### Git, история и автор коммита

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-GitBranch <string>` | Ветка результата. По умолчанию текущая ветка при сохранении истории; `main` при новой истории или в новом каталоге. | Да, если параметр отсутствует. Enter принимает предложенное имя. |
| `-FreshHistory` (`switch`) | Создать новую историю вместо истории шаблона. Прежний Git сохраняется в резервной копии. Значение без выбора — `false`; в отдельном новом каталоге история и так новая. | Да, только при инициализации в каталоге шаблона и отсутствии параметра. Enter — сохранить историю. |
| `-ProjectRemoteUrl <string>` | Установить `origin` проекта. Прежний отличающийся `origin` сохраняется как `bootstrap`. Сам по себе параметр не выполняет push. Без него существующий remote сохраняется, а у новой истории remote отсутствует. | Только в конце запуска без явно заданного `InfobaseType`, при инициализации в каталоге шаблона и без заданного URL. Enter оставляет текущие remotes. |
| `-GitUserName <string>` | Автор начального коммита. Без параметра используется настроенное имя Git, в том числе локальная настройка исходного клона. | Нет. При необходимости коммита и отсутствии настроенного автора Git выдаёт ошибку. |
| `-GitUserEmail <string>` | Email автора начального коммита. Без параметра используется настроенный email Git. | Нет. |
| `-SkipInitialCommit` (`switch`) | Не создавать коммит инициализации: подготовленные изменения остаются в индексе. Для новой истории Git остаётся без коммитов. По умолчанию `false`. | Нет. |

В клоне уже существующую другую ветку нужно выбрать через `git switch` до
инициализации. Параметр `GitBranch` не перезаписывает существующую ветку.
Имя и email Git не являются учётными данными для входа в информационную базу.

### Вход в файловую или серверную базу

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-UseOSAuthentication` (`switch`) | Вход от текущего пользователя Windows через `/WA+`, без `/N` и `/P`. | Если ни один способ входа не задан, предлагается выбор. Enter — вход ОС. Отказ включает запрос имени и пароля 1С. |
| `-AskCredential` (`switch`) | Запросить имя и скрыто пароль пользователя 1С. Для `File`/`Server` это пользователь ИБ; для `Repository` — пользователь выбранного источника. По умолчанию флаг выключен. | При включённом флаге — да. Для базы он также включается после отказа от входа ОС. Переданное имя предлагается как значение по умолчанию. |
| `-UserName <string>` | Имя пользователя ИБ. Передача включает явный режим входа по реквизитам 1С вместо выбора ОС. По умолчанию не задано. | Само имя — только с `AskCredential` либо после отказа от входа ОС. |
| `-Password <SecureString>` | Пароль пользователя ИБ. Допустим пустой пароль. Передавайте объект через PS1, а не строку через CMD. | Скрыто, если задано имя без пароля, включён `AskCredential` или выбран вход по имени вместо ОС. |

`UseOSAuthentication` доступен только для `File`/`Server` и несовместим с
`AskCredential`, `UserName`, `Password`. Имя и пароль передаются в режиме `/WA-`.
Явный `UseOSAuthentication:$false` подавляет выбор способа входа, но сам по себе
не включает запрос учётных данных: для этого задайте `AskCredential`.

### Параметры источника Repository

Эта группа доступна только с `-InfobaseType Repository`. Передача этих параметров
для `File`/`Server` отклоняется. Адрес основного источника задаётся через
`Infobase`; отдельного параметра `RepositoryAddress` нет.

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-RepositoryUserName <string>` | Имя пользователя для чтения. Для фактической выгрузки имя необходимо: передайте его или включите запрос учётных данных. | Только с `AskRepositoryCredential` или `AskCredential`. Переданное имя предлагается по умолчанию. |
| `-RepositoryPassword <SecureString>` | Пароль для чтения, включая пустой. Передаётся через PS1 как объект. | Скрыто при заданном имени без пароля либо через один из флагов запроса учётных данных. |
| `-AskRepositoryCredential` (`switch`) | Запросить имя и скрыто пароль для источника `Repository`. По умолчанию `false`; альтернатива — `AskCredential`. | Да, если флаг включён. |
| `-RepositoryVersion <int>` | Версия основной конфигурации: `-1` — последняя (по умолчанию), положительное число — заданная версия. `0` и числа меньше `-1` недопустимы. | Нет. |
| `-ExtensionRepositoryFile <string>` | Путь к JSON-массиву `name`, `url`, необязательный `version` для расширений. Без файла — пустой список. Для каждой записи версия по умолчанию `-1`. | Нет. Адреса расширений не обнаруживаются автоматически. |

### Выбор расширений

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-Extensions <string[]>` | Точные имена расширений для импорта. Массив удобнее передавать через PS1: `-Extensions @('ExtOne','ExtTwo')`. Без списка и без других флагов берутся все доступные расширения. | Нет. |
| `-SelectExtensions` (`switch`) | Показать список и выбрать расширения по номерам. По умолчанию `false`, но выбор автоматически включается при запуске без `InfobaseType`, если нет `Extensions` и `NoExtensions`. | Да: `1,3` — выбранные номера, `*` или Enter — все, `0` — ни одного. Если расширений нет, вопрос не задаётся. |
| `-NoExtensions` (`switch`) | Импортировать только основную конфигурацию. По умолчанию `false`. | Нет. |

`Extensions` несовместим с `NoExtensions`; `SelectExtensions` — с обоими.
`NoExtensions` также несовместим с `ExtensionRepositoryFile`. Выбор выполняется
после получения XML: исключённые из импорта расширения не преобразуются в EDT.

### Регистрация в EDT Start

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-RegisterEdtStart` (`switch`) | После создания проекта импортировать его в постоянную рабочую область и зарегистрировать в EDT Start. По умолчанию `false`. | Нет. |
| `-EdtWorkspaceDirectory <string>` | Каталог постоянной рабочей области. Используется с `RegisterEdtStart`; по умолчанию `<TargetDirectory>-workspace`. | Нет. |
| `-RestartEdtStart` (`switch`) | Разрешить остановку и повторный запуск работающего EDT Start при регистрации. Процессы самой EDT не останавливаются. Используется с `RegisterEdtStart`, по умолчанию `false`. | Нет. Без разрешения работающий EDT Start нужно закрыть самостоятельно. |

### Режим выполнения

| Параметр и тип | Назначение и значение по умолчанию | Запрашивается в консоли |
| --- | --- | --- |
| `-NonInteractive` (`switch`) | Отключить автоматические вопросы. Требует явных `InfobaseType`, `Infobase`, `DesignerPath`, `EdtCliPath`. По умолчанию `false`. | Нет. Явные флаги запроса ввода сохраняют действие, см. ниже. |
| `-Preview` (`switch`) | Показать рассчитанные настройки и завершиться до выгрузки, импорта и изменения проекта. По умолчанию `false`. | Не спрашивает способ входа, новую историю и ветку, не запрашивает пароли. Недостающие тип источника, адрес и пути программ всё ещё запрашиваются, если нет `NonInteractive`. |
| `-ResumeFrom <string>` | Каталог `.project-init-<UUID>` прерванного запуска. Восстанавливает настройки и повторно использует подтверждённые результаты XML/EDT. По умолчанию не задан. | Отдельного вопроса о продолжении нет. Недостающие сведения запрашиваются по обычным правилам. Пароли не сохраняются; при повторной выгрузке могут понадобиться снова. |
| `-NoGitLfs` (`switch`) | Отключить настройку Git LFS и удалить правила `filter=lfs` из подготовленных `.gitattributes`. По умолчанию `false`: LFS включён. | Нет. |
| `-TimeoutSeconds <int>` | Лимит в секундах для отдельного запуска внешней программы; передаётся и EDT CLI. По умолчанию `1800`, диапазон `30–86400`. Это не общий лимит всей инициализации. | Нет. Для большой конфигурации можно задать `14400` — четыре часа на операцию. |

С `NonInteractive` пропущенный `FreshHistory` означает сохранение истории,
а пропущенный `GitBranch` — текущую ветку либо `main` для новой истории.
Если способ входа не задан, используется стандартный режим платформы, без выбора
ОС. Явные `AskCredential`, `AskRepositoryCredential` и `SelectExtensions`
по-прежнему запрашивают ввод; для полностью автоматического запуска их не задавайте.
При заданном имени передайте соответствующий пароль, в том числе пустой
`SecureString`: без него скрипт завершится ошибкой вместо запроса.

### Какие вопросы появляются и в каком порядке

Некоторые вопросы пропускаются в зависимости от источника, режима и уже
переданных параметров. Подготовительные операции и проверки между ними могут
завершить запуск раньше следующего вопроса.

| Порядок | Вопрос | Когда появляется | Ответ по умолчанию |
| --- | --- | --- | --- |
| 1 | Тип источника | Не задан `InfobaseType`. | Нужно выбрать `1`, `2` или `3`. |
| 2 | Вход ОС | `File`/`Server`, способ входа не передан, нет `Preview`/`NonInteractive`. | `1` — да. |
| 3 | Адрес источника | Не задан `Infobase`. | Нет. |
| 4 | Путь к Конфигуратору | Не задан `DesignerPath`. | Нет. |
| 5 | Путь к EDT CLI | Не задан `EdtCliPath`. | Нет. |
| 6 | Новая история Git | Каталог шаблона, нет явного `FreshHistory`, нет `Preview`/`NonInteractive`. | `2` — сохранить историю. |
| 7 | Ветка Git | Нет явного `GitBranch`, нет `Preview`/`NonInteractive`. | Текущая ветка или `main`. |
| 8 | Имя и пароль | Включён запрос учётных данных, либо задано имя без пароля. | Предложенное имя; пароль вводится скрыто и может быть пустым. Без флага запроса при уже заданном имени спрашивается только пароль. |
| 9 | Выбор расширений | Включён `SelectExtensions` явно или автоматически, расширения обнаружены. | Все (`*`). |
| 10 | Git URL проекта | Проект уже создан в каталоге шаблона, URL не задан, запуск без явного `InfobaseType`, нет `NonInteractive`. | Не менять remotes. |

### Примеры явной передачи параметров

Серверная база, вход ОС, новая история, увеличенное время ожидания:

```powershell
.\initialize.cmd -InfobaseType Server -Infobase 'server:1541\demo' -DesignerPath 'C:\Tools\1C\bin\1cv8.exe' -EdtCliPath 'C:\Tools\EDT\1cedtcli.exe' -UseOSAuthentication -FreshHistory -GitBranch main -TimeoutSeconds 14400 -NonInteractive
```

Файловая база с именем, скрытым паролем и явным списком расширений. `Read-Host`
ниже выполняет вызывающий PowerShell; инициализатор получает готовый объект:

```powershell
$options = @{
    InfobaseType = 'File'
    Infobase = 'D:\Bases\Demo'
    DesignerPath = 'C:\Tools\1C\bin\1cv8.exe'
    EdtCliPath = 'C:\Tools\EDT\1cedtcli.exe'
    UserName = 'Developer'
    Password = Read-Host 'Пароль ИБ' -AsSecureString
    Extensions = @('ExtOne', 'ExtTwo')
    GitBranch = 'main'
    FreshHistory = $false
    NonInteractive = $true
}
.\project-init\Initialize-Project.ps1 @options
```

Для пустого пароля используйте `Password = (New-Object Security.SecureString)`.
При прямом вызове PS1 из корня форка без отдельного `TargetDirectory` шаблон
определяется автоматически. Имена и email Git должны быть заранее настроены
или переданы через `GitUserName` и `GitUserEmail`.

## Продолжение после ошибки и длинные пути

После завершившегося с ошибкой запуска сохраните каталог диагностики,
обновите инициализатор и передайте его путь:

```powershell
git pull --ff-only
.\initialize.cmd -ResumeFrom 'D:\repo\.project-init-de0544e68fd64c0fb03a98c73ebeddb2' -TimeoutSeconds 14400
```

В новых запусках `initialization.json` сохраняет настройки, выбор расширений
и состояние применения проекта. Пароли в него не записываются. Явные параметры
нового запуска имеют приоритет над сохранёнными, но изменение источника,
версии исходного снимка или пути Конфигуратора отклоняется: для них начните
отдельную инициализацию. Можно изменить, например, лимит ожидания или ветку Git.

Продолжение работает по этапам:

1. Если полные необходимые XML-выгрузки завершились с кодом `0`, без тайм-аута,
   и их каталоги доступны, они используются без повторного запуска Конфигуратора.
   Если набор XML не завершён, он выгружается заново целиком; частичный результат
   не смешивается с подтверждёнными выгрузками другого запуска.
2. Успешный импорт EDT используется повторно, если совпадают имя проекта,
   XML-каталог, путь CLI, ini-файл и основная конфигурация для расширения.
   Для незавершённого импорта CLI запускается повторно. Существование одной
   `.project` без успешного результата процесса не считается завершением.
3. Копирование и подготовка Git повторяются в новом временном каталоге.
   Старые выгрузки и журналы сохраняются. Новый журнал ссылается на предыдущий,
   поэтому продолжение можно повторить после следующей ошибки. Нужно свободное
   место для нового подготовленного проекта и его копии с окончаниями строк Windows.
4. Проект применяется только после успешного завершения подготовки.
   Продолжение уже работающего процесса запрещено. Если применение проекта
   уже началось или завершилось, повторное применение через `ResumeFrom`
   запрещено: проверьте проект и `fresh-history-publication.json`.

Повторно используемые XML — снимок предыдущего запуска. Они не обновляются
из изменившейся базы. Не редактируйте выгрузки и рабочую область EDT между
попытками и не запускайте инициализацию параллельно. Если нужен новый снимок,
запустите без `ResumeFrom`. При повторном выполнении незавершённых XML-выгрузок
источник также не должен изменяться до окончания нового набора выгрузок.

Для старых запусков `File`/`Server`, созданных до появления `initialization.json`,
источник и параметры импорта восстанавливаются по `*.launch.json`, а успешность
этапов — по `*.result.json`. Выбор расширений не записывался, поэтому его
может потребоваться повторить. Для старого запуска в отдельный каталог передайте
`-TargetDirectory` явно. При отсутствии необходимых журналов продолжение
отклоняется. Старые прямые запуски `Repository` без файла состояния требуют
новой инициализации; новые запуски этого режима сохраняют полноценный журнал.

Пути EDT могут превышать 260 символов: длинное имя формы входит и в каталог,
и в имя `.mdo`. Для переноса дерева используется Windows `robocopy`, а в
подготавливаемом Git включается `core.longpaths=true`. Изменение системной
политики длинных путей не требуется. Имена объектов и файлов не сокращаются.
Проверка включает длинные кириллические имена, запись в Git, повторное
использование завершённых этапов и повтор незавершённых.

## Выбор ветки при инициализации

Передайте `-GitBranch`, например:

```powershell
.\initialize.cmd -GitBranch main -AskCredential
```

При интерактивном запуске имя ветки также запрашивается с текущим значением
по умолчанию. Enter сохраняет текущую ветку клона при сохранении истории;
для новой истории или отдельного нового каталога предлагается `main`.
В режиме `NonInteractive` эти значения применяются без вопроса.
`-GitBranch develop` или `feature/start`
задаёт другое имя.

В клоне новая ветка создаётся из подготовленного коммита инициализации только
после успешной выгрузки и проверок. Исходная ветка остаётся на прежнем коммите.
Чтобы использовать уже существующую другую ветку, сначала переключитесь на неё
через `git switch`, затем запускайте инициализацию. Скрипт не перезаписывает
существующие ветки. С `-SkipInitialCommit` новая ветка остаётся на исходном
коммите, а подготовленные изменения находятся в индексе.

Отдельный репозиторий: `initialize.cmd -TargetDirectory D:\Projects\Other -GitBranch develop`.
Параметр не создаёт ветку на сервере Git и не выполняет push.

## Новый проект без истории шаблона

```powershell
.\initialize.cmd -FreshHistory -GitBranch main -AskCredential
```

`-FreshHistory` создаёт независимый Git в этом же каталоге: один начальный коммит
с готовым проектом, без старых коммитов, веток и remotes шаблона. Без флага
предлагается выбор с сохранением истории по умолчанию; с `NonInteractive`
история сохраняется без вопроса. По умолчанию новая ветка называется `main`; другое имя
задаётся через `-GitBranch`. `-SkipInitialCommit` оставляет новый Git без коммитов
с подготовленными файлами в индексе.

Сначала все исходники и Git готовятся во временном каталоге. Старый `.git`
сохраняется вне проекта в `.project-init-<UUID>/previous-project/.git`; путь
выводится после применения. Резервная копия содержит прежнюю историю и настройки,
не входит в новый репозиторий и не отправляется при push. После проверки её
можно удалить самостоятельно. Ошибка применения вызывает восстановление
прежних файлов и `.git`; сведения о публикации — в `fresh-history-publication.json`.

Режим доступен для самостоятельного клона без дополнительных Git worktrees.
Рабочая копия должна быть чистой, исходники и манифест должны отсутствовать.
Для подключения Git-сервера задайте `-ProjectRemoteUrl` либо выполните
`tools/git-project-init.cmd` после инициализации. При `-FreshHistory` старые
remotes остаются только в резервной копии. С явным другим `-TargetDirectory`
история и так создаётся заново, поэтому дополнительный флаг там не требуется.
